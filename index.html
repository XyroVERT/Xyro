Publish through the Xyro API not set

With a key saved, Publish writes through your Cloudflare Worker instead of GitHub: no GitHub login in the browser, no API rate limit, and the Worker drops its own cache as part of the write, so the change is live at once. It also refuses a stale publish (someone else editing meanwhile) instead of overwriting them. The Worker stores the rules itself, so no GitHub token is involved at all — if it also has a GH_TOKEN, your publishes are committed to the repo as well for history.
The admin key can also trip the kill switch and edit the blacklist, and this one lives in your browser. If you would rather it could do nothing but publish, set a separate XYRO_PUBLISH_KEY on the Worker and paste that here instead. Either way it is a password: use it on your own machine.

Blacklist not loaded

A blacklisted account is refused by the script itself: it shows the reason and stops loading, so nothing of Xyro runs for them. Usernames and numeric ids both work, and a blocked player cannot run the script to get around it. Editing needs your owner key (the card at the top) — deliberately not the public client key, or any player could block a rival.
Read-only for now: the Worker can read the list but has no credential to write the database, so nothing can be blocked from here. Set one on the Worker and this card becomes read-write: npx wrangler secret put FB_SERVICE_ACCOUNT (paste the whole service-account key file — api/README.md section 4), or the legacy FB_SECRET. Reading, the in-game !blocked list and the live-user filter already work; the Firebase console still edits it too.
